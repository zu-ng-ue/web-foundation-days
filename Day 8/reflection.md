# Reflection

The most difficult concept in this course was system design and scaling (Days 7 and 8). Moving from writing code that works on my own laptop to designing an architecture that serves millions of users was initially overwhelming. I overcame this by breaking the problem down into the six-part framework: defining requirements, estimating traffic, designing the API, modeling the data, drawing the architecture, and identifying trade-offs. I also learned that designing for scale requires accepting that things will fail, which is why we use load balancers, read replicas, and distributed caches.

If I were to improve one part of my capstone project based on feedback, I would focus on the UI/UX of the API client. While the functionality (GET, POST, DELETE) works perfectly, the design could be more user-friendly. I would add visual feedback like loading spinners and better error messages to make the app feel more polished.

Next, I want to learn how to deploy these architectures using cloud infrastructure. I plan to learn Docker and Kubernetes to containerize my applications, and I want to explore AWS or Google Cloud to understand how to set up real load balancers, databases, and CDNs in a production environment.
